# E-Commerce Test Automation Framework

A Selenium WebDriver + TestNG based automation framework built in Java to test an e-commerce web application, integrated with Jenkins for CI/CD.

## Overview

This framework follows the **Page Object Model (POM)** design pattern and is **data-driven**, using external JSON files as the source of test data. It is designed to run both locally and as part of an automated CI/CD pipeline, with results published to Jenkins on every push via a GitHub webhook.

| Maven                   | Build tool and dependency management                   |
| Maven Surefire Plugin   | Executes tests via `testng.xml`, generates reports for CI |

## Project Structure

```
src/test/java/com/automation/
 ├── tests/        → Test classes (@Test methods, @DataProvider)
 ├── pages/         → Page Object classes (locators + page actions)
 ├── pojo/          → POJOs representing test data models
 ├── utils/         → Helper classes (DriverManager, JsonDataReader, etc.)
 └── listeners/     → TestNG listeners (test lifecycle logging/reporting)

src/test/resources/
 └── testdata/      → JSON files used as data-driven test input

testng.xml          → TestNG suite configuration
pom.xml              → Maven build & dependency configuration
Jenkinsfile          → Jenkins pipeline/build configuration
```

## Design Approach

- **Page Object Model** — Each web page has a dedicated class exposing actions (`enterUsername()`, `clickLogin()`, etc.). Test classes call these actions and handle assertions; page classes never assert.
- **Data-Driven Testing** — Test data lives in JSON files, decoupled from test logic. A `JsonDataReader` utility (Jackson `ObjectMapper`) deserializes JSON into typed POJOs, which are fed into tests via TestNG's `@DataProvider`.
- **Centralized Driver Management** — `DriverManager` handles WebDriver creation and teardown in one place, making it easy to switch browsers or run headless in CI without touching test code.
- **Listeners** — A custom `TestListener` (implementing `ITestListener`) logs test start/pass/fail/skip events, wired into `testng.xml`.

## Running Tests

**Locally, via Maven:**
```bash
mvn clean test
```

**Run a specific suite:**
```bash
mvn clean test -DsuiteXmlFile=testng.xml
```

Test results are generated by the Maven Surefire plugin under:
```
target/surefire-reports/
```

## CI/CD Pipeline

1. Code is pushed to GitHub.
2. A GitHub webhook triggers a Jenkins **Freestyle** build.
3. Jenkins runs the Maven build (`mvn clean test`), which executes the TestNG suite via Surefire.
4. Surefire reports are published in Jenkins for pass/fail tracking.

## Sample Test Flow

```
loginData.json  →  JsonDataReader  →  LoginData (POJO)  →  @DataProvider  →  @Test (LoginTest)
```

`LoginTest` uses `LoginPage` to interact with the login form and asserts the expected outcome (success/failure) based on the data supplied.
